# Подготовка новой Neon PostgreSQL

Для облачного контейнера `deploy/docker/Dockerfile.cloud` база заполняется заранее.
В образе нет большого файла векторов. Используйте отдельный проект Neon, PostgreSQL 16,
и прямое подключение без pooler. Локальная рабочая база в этих командах не используется.

## Чистая резервная копия

Из корня проекта соберите текущий образ, затем подготовьте словарь:

```sh
docker build -f deploy/docker/Dockerfile.cloud -t guessword-cloud:local .
python tools/deploy/prepare_dictionary.py \
  --vector-file /absolute/path/to/sociation2vec800.vec \
  --output-dir /absolute/path/outside-git/new-dictionary-backup
```

Требуются Docker, локальный образ `pgvector/pgvector:pg16` и Python 3.11+.
Скрипт использует отдельные контейнеры, БД и volume со случайными именами; удаляет только
созданные им ресурсы. Рабочее подключение приложения не читается. Векторы монтируются
read-only, не копируются в Git или образ. Существующий каталог резервных копий не перезаписывается.

Результат: `dictionary.dump` и `manifest.json` с SHA256, миграциями и отпечатком словаря.
В БД должны быть только схема и словарь: аккаунты, игры, история и комнаты пусты.
Копия принимается только после восстановления в другую отдельную БД, сравнения содержимого
и успешного `/health/ready` текущего контейнера без файла векторов. Сохраните оба файла
вместе, вне Git и образов; проверенный дамп можно дополнительно сохранить на другом носителе.

## Локальный файл подключения

В Neon откройте нужный проект и ветку, нажмите **Connect**, отключите **Connection pooling**.
Скопируйте только URI `postgresql://...`, без команды `psql` и внешних кавычек.
Пароль и URI не отправляйте в чат или на скриншотах.

Заполните игнорируемый `.env.deploy.local` в корне проекта:

```dotenv
NEON_DATABASE_URL=<direct-postgresql-URI-from-Neon>
NEON_EXPECTED_HOST=<same-direct-host-from-selected-branch>
NEON_EXPECTED_DATABASE=neondb
```

Второе поле — только hostname без протокола, порта и `/neondb`. Убедитесь в панели, что это
именно выбранные проект и ветка: сервер PostgreSQL не подтверждает название проекта Neon.
Файл должен принадлежать текущему пользователю и иметь права `600`:

```sh
chmod 600 .env.deploy.local
```

Файл читается как данные, не исполняется как shell. Не добавляйте его в коммит.

## Проверка и импорт — после отдельного разрешения на подключение

Требуются локальный `psql` с channel binding, системные CA, Docker и тот же локальный образ
PostgreSQL 16 для чтения архива. Проверка цели выполняет только чтение:

```sh
python tools/deploy/import_neon_dictionary.py
```

Обязательны прямой адрес Neon, PostgreSQL 16, TLS `verify-full` с проверкой имени сервера
и channel binding. Даже если URI из панели содержит `sslmode=require`, скрипт усиливает
проверку до `verify-full`. При ошибке сертификата не отключайте проверку TLS.

После проверки цели, резервной копии и разрешения на запись:

```sh
python tools/deploy/import_neon_dictionary.py --apply \
  --dump /absolute/path/outside-git/new-dictionary-backup/dictionary.dump \
  --manifest /absolute/path/outside-git/new-dictionary-backup/manifest.json \
  --confirm-target ep-EXACT-DIRECT-HOST.eu-central-1.aws.neon.tech/neondb
```

Замените подтверждение точным hostname и именем выбранной БД. В командной строке нет
пароля или URI. Пароль передаётся libpq через временный защищённый pgpass-файл, который
удаляется после выполнения. Вывод ошибок дочерних команд скрывается, поскольку может
содержать секреты или строки данных.

Импорт повторно проверяет цель внутри одной транзакции, восстанавливает собственный дамп
и сравнивает миграции, словарь, векторы и пустые пользовательские таблицы до COMMIT.
При ошибке транзакция откатывается. У скрипта нет опций удаления/очистки чужих объектов.
Если обнаружены таблицы, представления, последовательности, функции, типы, посторонние
схемы или расширения, импорт останавливается. Повторный запуск на заполненной БД отклоняется.
Не создавайте таблицы вручную и не запускайте API одновременно с первоначальным импортом.

После импорта отдельно проверьте готовность приложения и использование диска в Neon:
`pg_database_size` не включает все квоты и служебные расходы облачного тарифа.
Для `ConnectionStrings__DefaultConnection` приложения позже подготовьте строку **Npgsql**
с TLS VerifyFull; сырой URI из этого файла не подставляется в настройки .NET.

Порядок и флаги сверены с официальными инструкциями
[Neon pg_dump/pg_restore](https://neon.com/docs/import/migrate-from-postgres) и
[PostgreSQL TLS](https://www.postgresql.org/docs/current/libpq-ssl.html).
